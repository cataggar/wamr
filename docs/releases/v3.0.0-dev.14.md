# WAMR 3.0.0-dev.14

Development prerelease. The AOT format and compiler/runtime interfaces are not
stable-release compatibility commitments.

## Correctness

- Unsigned constant division and remainder now use a proven reciprocal bound
  instead of sampled validation. Unsupported reciprocal forms retain the correct
  hardware-division fallback. This fixes decimal-output corruption for affected
  values, including the threaded-workload checksum formatter (#1011).
- AOT cancellation polls cover function entries as well as loop back-edges, so
  recursive guests participate in cancellation. Cancellation publication is
  serialized to avoid losing requests during concurrent execution (#1010, #1019).
- SIMD sqrt conformance distinguishes canonical and arithmetic NaNs rather than
  requiring identical implementation-selected payloads. Deterministic abs/neg
  assertions remain bit-exact; this correction does not alter code generation
  (#1021).

Regenerate precompiled `.cwasm` artifacts and compiler caches with this release.
Incompatible AOT artifacts and stale codegen-cache entries are rejected rather
than treated as interchangeable with the new compiler/runtime.

## Execution modes and diagnostics

Published command-line binaries retain the default AOT workflow: compile with
`wamrc`, then execute the `.cwasm` with `wamr`. In-process JIT remains an opt-in
source-build mode (`-Djit=true`); WASI threads are also opt-in
(`-Dlib_wasi_threads=true`). See the installation and WASI documentation for
supported configurations.

ARM profiling now supports exact frame-origin metadata and paired baseline/target
captures. These diagnostics are not evidence of a runtime speedup. No speculative
spill-reload optimization is included.

## Known limitations

- Native SIMD AOT coverage remains AArch64-only; the x86_64 backend rejects
  retained v128 IR.
- Component host-import trampoline support is limited on Windows and macOS
  AArch64. Core-module smoke coverage does not establish full component support.
- Cross-built release targets are not all executed by the release matrix.
  Consult the release manifest for the exact native and signing coverage.
- Thread-enabled performance and cancellation costs remain under calibration
  (#963, #966). No negligible-cost or throughput claim is made.
- The ARM CoreMark and pinned SpiderMonkey/TCGC performance goals remain open
  (#949, #798). The deferred WASI scope in #972 remains deferred.

PyPI publication remains stable-only; this development prerelease is not a claim
of published or validated Python wheels.
